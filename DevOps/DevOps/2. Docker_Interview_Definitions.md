# Docker Interview Definitions

## 1. What is Docker?

**Definition:**  
Docker is a **containerization platform** that packages an application along with its dependencies into lightweight, portable, and isolated containers.

**Interview Answer:**  
> “Docker is a containerization platform used to package applications and their dependencies into lightweight, portable containers. It helps ensure that an application runs consistently across different environments.”

---

## 2. What is a Container?

**Definition:**  
A container is a **lightweight, isolated runtime environment** that contains an application and everything required to run it, while sharing the host operating system's kernel.

**Interview Answer:**  
> “A container is an isolated environment used to run an application along with its dependencies. Unlike a virtual machine, a container shares the host operating system kernel, making it lightweight and faster to start.”

---

## 3. Container vs VM

**Definition:**  
A **container** shares the host OS kernel, while a **virtual machine** includes a complete guest operating system running on virtualized hardware.

| Container | Virtual Machine |
|---|---|
| Shares host OS kernel | Has its own guest OS |
| Lightweight | Heavier |
| Starts quickly | Takes longer to start |
| Uses fewer resources | Uses more resources |
| Container-level isolation | Hardware/VM-level isolation |
| Container runtime | Hypervisor |

**Interview Answer:**  
> “Containers share the host operating system kernel and are lightweight, while virtual machines run a complete guest operating system on virtualized hardware. Therefore, containers generally start faster and consume fewer resources than VMs.”

---

## 4. Docker Architecture

**Definition:**  
Docker architecture is based on a **client-server model** consisting mainly of the **Docker Client, Docker Daemon, Docker Host, and Docker Registry**.

**Basic flow:**

```text
Docker Client
     ↓
Docker Daemon
     ↓
Docker Images / Containers
     ↓
Docker Registry
```

**Interview Answer:**  
> “Docker uses a client-server architecture. The Docker Client sends commands to the Docker Daemon, which manages images, containers, networks, and volumes. Images can be pulled from or pushed to a Docker Registry such as Docker Hub.”

---

## 5. Docker Engine

**Definition:**  
Docker Engine is the **core technology that builds, runs, and manages Docker containers**.

**Interview Answer:**  
> “Docker Engine is the core container runtime and management platform that allows users to build images, create and run containers, and manage Docker resources such as networks and volumes.”

---

## 6. Docker Image

**Definition:**  
A Docker image is an **immutable, read-only template containing the application code, dependencies, libraries, and configuration required to create a container.**

**Interview Answer:**  
> “A Docker image is a read-only template used to create containers. It contains the application and its required dependencies and is usually built from a Dockerfile.”

**Example:**

```text
Docker Image
     ↓
Docker Container
```

---

## 7. Docker Container

**Definition:**  
A Docker container is a **running or stopped instance of a Docker image** with its own isolated filesystem, processes, networking, and configuration.

**Interview Answer:**  
> “A Docker container is an instance of a Docker image. It provides an isolated environment in which an application runs along with its required dependencies.”

---

## 8. Dockerfile

**Definition:**  
A Dockerfile is a **text file containing instructions used to build a Docker image automatically.**

**Interview Answer:**  
> “A Dockerfile is a text file that contains instructions for building a Docker image. It defines things such as the base image, application files, dependencies, ports, environment variables, and startup command.”

**Example:**

```dockerfile
FROM python:3.12

WORKDIR /app

COPY . .

RUN pip install -r requirements.txt

EXPOSE 5000

CMD ["python", "app.py"]
```

---

## 9. Docker Hub

**Definition:**  
Docker Hub is a **cloud-based public registry and repository service** provided by Docker for storing, sharing, and distributing container images.

**Interview Answer:**  
> “Docker Hub is Docker's cloud-based image registry where developers can store, share, and download container images. It contains both public and private repositories.”

---

## 10. Docker Registry

**Definition:**  
A Docker Registry is a **storage and distribution system for Docker images**.

**Interview Answer:**  
> “A Docker Registry is a service used to store and distribute Docker images. Docker Hub is a public cloud registry, while organizations can also run private registries for internal image storage.”

**Examples:**
- Docker Hub
- Amazon ECR
- GitHub Container Registry
- Google Artifact Registry
- Azure Container Registry

---

## 11. Docker Volumes

**Definition:**  
Docker volumes are **persistent storage mechanisms managed by Docker that allow data to survive beyond the lifecycle of a container.**

**Interview Answer:**  
> “Docker volumes provide persistent storage for containers. They allow application data to remain available even when a container is stopped, deleted, or recreated.”

**Example:**

```bash
docker volume create mydata
```

---

## 12. Docker Networks

**Definition:**  
Docker networks provide **communication between containers and control how containers communicate with each other, the host, and external networks.**

**Interview Answer:**  
> “Docker networks provide networking and isolation for containers. They allow containers to communicate with each other and with external systems according to the configured network type.”

**Common network types:**
- Bridge
- Host
- None
- Overlay

---

## 13. Container Ports

**Definition:**  
A container port is a **network port on which an application inside a container listens for connections**. It can be mapped to a port on the Docker host to make the application accessible externally.

**Interview Answer:**  
> “A container port is the port on which an application listens inside the container. Docker can map that container port to a host port so users can access the application from outside the container.”

**Example:**

```bash
docker run -p 8080:80 nginx
```

Here:

```text
Host Port       Container Port
   8080    →         80
```

---

## 14. Environment Variables

**Definition:**  
Environment variables are **key-value configuration values provided to a container at runtime** without modifying the application image.

**Interview Answer:**  
> “Environment variables are used to provide runtime configuration to containers, such as application settings, database connection details, or environment-specific values. They help separate configuration from the application image.”

**Example:**

```bash
docker run -e APP_ENV=production myapp
```

Inside the container:

```text
APP_ENV=production
```

> **Security note:** Sensitive secrets such as passwords, API keys, and tokens should not be hard-coded into Dockerfiles or images.

---

## 15. Container Lifecycle

**Definition:**  
The container lifecycle describes the different **states and operations a Docker container goes through from creation to removal**.

**Typical lifecycle:**

```text
Image
  ↓
Create
  ↓
Start
  ↓
Running
  ↓
Stop
  ↓
Restart
  ↓
Remove
```

**Interview Answer:**  
> “The Docker container lifecycle starts when a container is created from an image, then started and run. It can be stopped, restarted, or paused as required. When it is no longer needed, it can be removed.”

**Common commands:**

```bash
docker create
docker start
docker run
docker stop
docker restart
docker pause
docker unpause
docker rm
```

**Important distinction:**

> **Image = template**  
> **Container = instance created from the image**
