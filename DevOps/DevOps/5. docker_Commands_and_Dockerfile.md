# Docker Commands and Dockerfile

## Docker Commands

| Command | Description |
|---|---|
| `docker --version` | Displays the installed Docker version. |
| `docker version` | Displays detailed version information for the Docker client and server/daemon. |
| `docker info` | Displays detailed information about the Docker environment, containers, images, storage, CPU, memory, etc. |
| `docker help` | Displays help for Docker commands. |
| `docker login` | Logs in to a Docker registry such as Docker Hub. |
| `docker logout` | Logs out from a Docker registry. |
| `docker search <image>` | Searches Docker Hub for available images. |
| `docker pull <image>` | Downloads an image from a Docker registry to the local system. |
| `docker push <image>` | Uploads a locally built image to a Docker registry. |
| `docker images` | Lists all Docker images available locally. |
| `docker image ls` | Lists local Docker images; equivalent to `docker images`. |
| `docker image pull <image>` | Pulls an image from a registry. |
| `docker image push <image>` | Pushes an image to a registry. |
| `docker image inspect <image>` | Displays detailed information about an image. |
| `docker image rm <image>` | Removes a Docker image from the local system. |
| `docker rmi <image>` | Removes a Docker image; shortcut for `docker image rm`. |
| `docker image prune` | Removes unused/dangling images. |
| `docker build -t <name> .` | Builds a Docker image from a Dockerfile and assigns it a name/tag. |
| `docker build -t <name>:<tag> .` | Builds an image with a specific name and tag. |
| `docker tag <image> <repository>:<tag>` | Creates another tag/reference for an existing image. |
| `docker history <image>` | Shows the layers that make up a Docker image. |
| `docker inspect <container/image>` | Displays detailed low-level information about a container or image. |
| `docker create <image>` | Creates a container from an image without starting it. |
| `docker run <image>` | Creates and starts a new container from an image. |
| `docker run -d <image>` | Runs a container in detached/background mode. |
| `docker run -it <image>` | Runs a container interactively with a terminal. |
| `docker run --name <name> <image>` | Creates a container with a custom name. |
| `docker run -p 8080:80 <image>` | Maps host port `8080` to container port `80`. |
| `docker run -v <host>:<container> <image>` | Mounts a host directory or volume inside the container. |
| `docker run --env KEY=value <image>` | Passes an environment variable to the container. |
| `docker run --restart always <image>` | Configures the container to restart automatically according to the restart policy. |
| `docker start <container>` | Starts an existing stopped container. |
| `docker stop <container>` | Gracefully stops a running container. |
| `docker restart <container>` | Stops and starts a container again. |
| `docker kill <container>` | Immediately terminates a running container. |
| `docker pause <container>` | Pauses all processes inside a container. |
| `docker unpause <container>` | Resumes a paused container. |
| `docker rm <container>` | Removes a stopped container. |
| `docker rm -f <container>` | Forcefully removes a running or stopped container. |
| `docker ps` | Lists currently running containers. |
| `docker ps -a` | Lists all containers, including stopped containers. |
| `docker ps -q` | Displays only container IDs. |
| `docker logs <container>` | Displays logs generated by a container. |
| `docker logs -f <container>` | Continuously follows/streams container logs. |
| `docker exec <container> <command>` | Executes a command inside a running container. |
| `docker exec -it <container> bash` | Opens an interactive Bash shell inside a running container. |
| `docker exec -it <container> sh` | Opens an interactive `sh` shell inside a running container. |
| `docker attach <container>` | Attaches your terminal to the main process of a running container. |
| `docker cp <container>:<path> <host-path>` | Copies files from a container to the host. |
| `docker cp <host-path> <container>:<path>` | Copies files from the host into a container. |
| `docker top <container>` | Displays processes running inside a container. |
| `docker stats` | Displays real-time CPU, memory, network, and I/O usage of containers. |
| `docker port <container>` | Displays the port mappings of a container. |
| `docker rename <old> <new>` | Renames a container. |
| `docker update <container>` | Updates configuration/resource limits of an existing container. |
| `docker container ls` | Lists containers. |
| `docker container inspect <container>` | Displays detailed information about a container. |
| `docker container prune` | Removes all stopped containers. |
| `docker volume ls` | Lists Docker volumes. |
| `docker volume create <name>` | Creates a new Docker volume. |
| `docker volume inspect <name>` | Displays detailed information about a volume. |
| `docker volume rm <name>` | Removes a Docker volume. |
| `docker volume prune` | Removes unused Docker volumes. |
| `docker network ls` | Lists Docker networks. |
| `docker network create <name>` | Creates a new Docker network. |
| `docker network inspect <name>` | Displays detailed information about a Docker network. |
| `docker network connect <network> <container>` | Connects a container to a Docker network. |
| `docker network disconnect <network> <container>` | Disconnects a container from a Docker network. |
| `docker network rm <name>` | Removes a Docker network. |
| `docker network prune` | Removes unused Docker networks. |
| `docker system df` | Displays Docker disk-space usage. |
| `docker system prune` | Removes unused Docker objects such as stopped containers, unused networks, and dangling images. |
| `docker system prune -a` | Removes unused Docker objects, including unused images. |
| `docker events` | Displays real-time Docker daemon events. |
| `docker wait <container>` | Waits until a container stops and displays its exit code. |
| `docker diff <container>` | Shows files that have been added, modified, or deleted inside a container. |
| `docker export <container> -o <file>` | Exports a container's filesystem as a tar archive. |
| `docker import <file>` | Creates a Docker image from a tar archive. |
| `docker save -o <file> <image>` | Saves a Docker image as a tar archive. |
| `docker load -i <file>` | Loads a Docker image from a tar archive. |
| `docker commit <container> <image>` | Creates a new image from the current state of a container. |
| `docker compose up` | Creates and starts services defined in a Docker Compose file. |
| `docker compose up -d` | Starts Docker Compose services in detached/background mode. |
| `docker compose down` | Stops and removes containers, networks, and other resources created by Compose. |
| `docker compose ps` | Lists containers belonging to a Compose project. |
| `docker compose logs` | Displays logs from Compose services. |
| `docker compose logs -f` | Continuously follows Compose service logs. |
| `docker compose build` | Builds images defined in the Compose file. |
| `docker compose pull` | Pulls images required by Compose services. |
| `docker compose restart` | Restarts Compose services. |
| `docker compose stop` | Stops Compose services without removing them. |
| `docker compose start` | Starts previously stopped Compose services. |
| `docker compose exec <service> <command>` | Executes a command inside a running Compose service container. |
| `docker compose config` | Validates and displays the resolved Docker Compose configuration. |
| `docker compose version` | Displays the installed Docker Compose version. |

# Dockerfile Instructions

| Dockerfile Instruction | Description |
|---|---|
| `FROM` | Specifies the base image from which the Docker image is built. Usually the first instruction in a Dockerfile. |
| `RUN` | Executes a command during image building and creates a new image layer. Commonly used to install packages or dependencies. |
| `CMD` | Specifies the default command that runs when a container starts. It can be overridden when running the container. |
| `ENTRYPOINT` | Specifies the main executable/application of the container. It is generally harder to override than `CMD`. |
| `COPY` | Copies files or directories from the build context into the Docker image. |
| `ADD` | Copies files/directories into the image and supports additional features such as extracting local tar archives. `COPY` is generally preferred for simple copying. |
| `WORKDIR` | Sets the working directory for subsequent `RUN`, `CMD`, `ENTRYPOINT`, `COPY`, and `ADD` instructions. |
| `ENV` | Defines environment variables that are available inside the image and containers created from it. |
| `ARG` | Defines a build-time variable that can be passed while building the image using `docker build --build-arg`. |
| `EXPOSE` | Documents the network port that the application inside the container is intended to listen on. It does not publish the port to the host. |
| `USER` | Specifies the user and optionally group under which subsequent commands and the container process will run. |
| `VOLUME` | Declares a mount point for persistent or externally managed data. |
| `LABEL` | Adds metadata to the Docker image, such as version or description. |
| `ONBUILD` | Specifies an instruction that is triggered when the current image is used as a base image for another image. |
| `STOPSIGNAL` | Specifies the system call signal that Docker should send to stop the container. |
| `HEALTHCHECK` | Defines a command Docker can use to check whether the containerized application is healthy. |
| `SHELL` | Changes the default shell used by shell-form commands such as `RUN`, `CMD`, and `ENTRYPOINT`. |

## Example Dockerfile

```dockerfile
# Base image
FROM ubuntu:24.04

# Set environment variable
ENV APP_ENV=production

# Set working directory
WORKDIR /app

# Copy application files
COPY . /app

# Install dependencies
RUN apt update && apt install -y python3

# Document application port
EXPOSE 8080

# Run application
CMD ["python3", "app.py"]
```

## CMD vs ENTRYPOINT

| Instruction | Purpose | Can be overridden? |
|---|---|---|
| `CMD` | Provides the default command or arguments. | Yes |
| `ENTRYPOINT` | Defines the main executable of the container. | Yes, but normally requires explicitly overriding the entrypoint. |

Example:

```dockerfile
ENTRYPOINT ["python3"]
CMD ["app.py"]
```

Docker runs:

```text
python3 app.py
```

If you run:

```bash
docker run myimage another.py
```

the `CMD` is replaced, resulting in:

```text
python3 another.py
```

```text
RUN        → Build time
CMD        → Default runtime command
ENTRYPOINT → Main runtime executable
```
