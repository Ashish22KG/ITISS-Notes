# Linux — Interview Definitions & Answers

Linux is a high-priority foundation for **Red Team, Blue Team/SOC, Cloud, DevSecOps, and Security Engineering** roles.

---

# 1. Linux Filesystem

**Definition:**  
The Linux filesystem is a hierarchical directory structure that starts from the root directory `/`. Files and directories are organized below this root.

**Important directories:**

| Directory | Purpose |
|---|---|
| `/` | Root of the entire filesystem |
| `/etc` | System and application configuration |
| `/var` | Variable data such as logs, caches, queues |
| `/home` | Personal directories of normal users |
| `/tmp` | Temporary files |
| `/proc` | Virtual filesystem exposing process and kernel information |
| `/dev` | Device files |
| `/bin` | Essential user commands on systems where this is separate |
| `/sbin` | Essential system administration commands on systems where this is separate |
| `/usr` | Most user-space applications, libraries, and data |
| `/opt` | Optional/add-on software |
| `/boot` | Bootloader and kernel-related files |
| `/root` | Home directory of the root user |
| `/mnt` | Temporary mount points |
| `/media` | Common mount location for removable media |

**Interview Answer:**  
"Linux uses a hierarchical filesystem that starts at `/`. Important directories include `/etc` for configuration, `/var` for variable data and logs, `/home` for user directories, `/tmp` for temporary files, `/proc` for kernel and process information, and `/dev` for device files."

---

# 2. `/etc`

**Definition:**  
`/etc` contains system-wide configuration files and configuration directories.

**Examples:**
- `/etc/passwd` — user account information
- `/etc/group` — group information
- `/etc/hosts` — local hostname-to-IP mappings
- `/etc/ssh/` — SSH configuration
- `/etc/systemd/` — systemd-related configuration
- `/etc/crontab` — system-wide cron configuration

**Interview Answer:**  
"`/etc` contains system-wide configuration. During security investigations, files under `/etc` can be important because they reveal authentication, network, service, SSH, and scheduled-task configuration."

**Security Relevance:**  
Attackers and defenders may inspect configuration files for credentials, insecure settings, persistence mechanisms, and service configuration.

---

# 3. `/var`

**Definition:**  
`/var` stores data that changes during normal system operation.

**Examples:**
- `/var/log/` — logs
- `/var/cache/` — cached data
- `/var/lib/` — persistent application state
- `/var/spool/` — queued/spooled data

**Interview Answer:**  
"`/var` contains variable data generated or changed while the system runs. `/var/log` is particularly important for security because it can contain authentication, system, application, and service logs."

---

# 4. `/home`

**Definition:**  
`/home` normally contains the home directories of non-root users.

**Example:**

```text
/home/ashish
/home/user1
/home/user2
```

**Interview Answer:**  
"`/home` stores users' personal files and user-specific configuration. Permissions on these directories help prevent one user from accessing another user's private data."

**Security Relevance:**  
Home directories can contain SSH keys, shell history, configuration files, scripts, and application credentials, so permissions and secrets should be handled carefully.

---

# 5. `/tmp`

**Definition:**  
`/tmp` is used for temporary files created by users and applications.

**Interview Answer:**  
"`/tmp` provides a location for temporary data. Because many processes and users may interact with temporary files, applications must use secure temporary-file practices and appropriate permissions."

**Security Relevance:**  
Security teams often inspect `/tmp` during incident response because malicious or suspicious files may be placed there. This does not mean every file in `/tmp` is malicious.

---

# 6. `/proc`

**Definition:**  
`/proc` is a virtual filesystem that exposes information about processes, the kernel, and system state.

**Examples:**
- `/proc/cpuinfo` — CPU information
- `/proc/meminfo` — memory information
- `/proc/uptime` — system uptime
- `/proc/<PID>/` — information about a specific process

**Interview Answer:**  
"`/proc` is a virtual filesystem generated by the kernel. It provides runtime information about processes and system resources and is useful for troubleshooting and security investigations."

**Security Relevance:**  
It can help analysts inspect running processes, command-line arguments, process relationships, and system information.

---

# 7. `/dev`

**Definition:**  
`/dev` contains device files that provide interfaces to hardware devices and certain kernel-managed resources.

**Examples:**
- `/dev/sda` — commonly a disk device
- `/dev/null` — discards written data
- `/dev/random` — random-data interface
- `/dev/tty` — terminal interface

**Interview Answer:**  
"`/dev` contains device files used by applications and the kernel to interact with devices and special resources. Linux represents many devices through file-like interfaces."

---

# 8. Users and Groups

**Definition:**  
Linux uses users and groups to control identity and access to files, processes, and system resources.

**Important concepts:**
- **User** — an identity/account
- **UID** — numeric user identifier
- **Group** — collection of users
- **GID** — numeric group identifier
- **root** — privileged administrative account

**Useful commands:**

```bash
whoami
id
who
w
groups
cat /etc/passwd
cat /etc/group
```

**Interview Answer:**  
"Linux uses users and groups as part of its access-control model. Every user has a UID and can belong to one or more groups. File permissions can then control access for the owner, group, and others."

---

# 9. Linux Permissions

**Definition:**  
Linux permissions control whether users can read, write, or execute files and directories.

**Three basic permission types:**

| Permission | Symbol | Meaning |
|---|---|---|
| Read | `r` | Read file contents / list directory entries |
| Write | `w` | Modify file / modify directory entries |
| Execute | `x` | Execute file / access directory |

**Three permission classes:**
- Owner
- Group
- Others

**Example:**

```text
-rwxr-xr--
```

This means:
- Owner: `rwx`
- Group: `r-x`
- Others: `r--`

**Interview Answer:**  
"Linux permissions are generally represented for the owner, group, and others. Each class can have read, write, and execute permissions. This provides basic access control over files and directories."

---

# 10. `chmod`

**Definition:**  
`chmod` changes the permissions of files and directories.

**Symbolic examples:**

```bash
chmod u+x script.sh
chmod g-w file.txt
chmod o-r secret.txt
```

**Numeric example:**

```bash
chmod 755 script.sh
```

`755` means:

```text
Owner  = 7 = rwx
Group  = 5 = r-x
Others = 5 = r-x
```

**Interview Answer:**  
"`chmod` changes file or directory permissions. It can use symbolic notation such as `u+x` or numeric notation such as `755`."

**Security Relevance:**  
Incorrect permissions can expose sensitive files or allow unauthorized modification or execution.

---

# 11. `chown`

**Definition:**  
`chown` changes the owner and optionally the group of a file or directory.

**Examples:**

```bash
chown user file.txt
chown user:group file.txt
```

**Interview Answer:**  
"`chown` changes file ownership. It is useful when configuring services or correcting ownership so that only the intended user or service account can access resources."

---

# 12. `sudo`

**Definition:**  
`sudo` allows an authorized user to execute commands with another user's privileges, commonly root privileges, according to configured policy.

**Example:**

```bash
sudo systemctl restart nginx
```

**Interview Answer:**  
"`sudo` provides controlled privilege elevation. Instead of giving users the root password or requiring them to operate as root all the time, administrators can grant specific users or groups permission to execute approved commands."

**Security Relevance:**  
The `sudoers` configuration should follow least privilege. Excessive sudo permissions can create privilege-escalation opportunities.

---

# 13. Processes

**Definition:**  
A process is a running instance of a program.

**Important concepts:**
- PID — Process ID
- PPID — Parent Process ID
- CPU usage
- Memory usage
- Process state
- User running the process

**Useful commands:**

```bash
ps aux
ps -ef
top
htop
pgrep nginx
pstree
kill <PID>
```

**Interview Answer:**  
"A process is a running program with its own process ID and execution context. Linux provides tools such as `ps`, `top`, `htop`, and `pstree` to inspect processes."

**Security Relevance:**  
Process analysis is important for identifying unexpected programs, suspicious command lines, abnormal parent-child relationships, and malware.

---

# 14. Services

**Definition:**  
A service is a background program that provides a system or network function, often running continuously or on demand.

**Examples:**
- SSH
- Web server
- Database server
- DNS server

**Interview Answer:**  
"A Linux service is a background process that provides a specific function. Services can be started, stopped, restarted, enabled, or disabled depending on how they are managed."

---

# 15. systemd

**Definition:**  
systemd is a Linux system and service manager used by many modern Linux distributions to initialize the system and manage services.

**Useful commands:**

```bash
systemctl status ssh
systemctl start ssh
systemctl stop ssh
systemctl restart ssh
systemctl enable ssh
systemctl disable ssh
systemctl list-units --type=service
```

**Interview Answer:**  
"systemd manages system initialization and services on many modern Linux distributions. `systemctl` is commonly used to control and inspect systemd units."

**Security Relevance:**  
Security teams can inspect enabled services, service configuration, startup behavior, and logs to identify unnecessary services or persistence mechanisms.

---

# 16. Cron

**Definition:**  
Cron is a scheduling mechanism used to execute commands or scripts automatically at specified times or intervals.

**Examples:**

```bash
crontab -l
crontab -e
```

A cron schedule has five time fields:

```text
minute hour day-of-month month day-of-week
```

**Example:**

```text
0 2 * * * /path/to/backup.sh
```

This schedules the command at 02:00 every day.

**Interview Answer:**  
"Cron is used to schedule recurring tasks. It is commonly used for backups, maintenance, and automation."

**Security Relevance:**  
During incident response, cron jobs should be reviewed because attackers can abuse scheduled tasks for persistence.

---

# 17. Environment Variables

**Definition:**  
Environment variables are key-value pairs provided to processes to configure their runtime environment.

**Examples:**

```bash
echo $PATH
echo $HOME
echo $USER
printenv
env
```

Set a variable for the current shell:

```bash
export APP_ENV=production
```

**Interview Answer:**  
"Environment variables provide runtime configuration to processes. Common examples include `PATH`, `HOME`, and `USER`."

**Security Relevance:**  
Environment variables may contain sensitive information such as API keys or credentials. Secrets should not be exposed unnecessarily through environment variables, process inspection, logs, or shell history.

---

# 18. SSH

**Definition:**  
SSH (Secure Shell) is a protocol used for secure remote login and other secure communication over a network.

**Common Port:**  
22/TCP

**Example:**

```bash
ssh user@192.168.1.10
```

**Interview Answer:**  
"SSH provides encrypted remote access to systems. It supports authentication methods such as passwords and public-key authentication. In security-focused environments, SSH configuration should be hardened and access should be restricted."

**Security Relevance:**
- Brute-force attempts
- Stolen credentials
- Weak authentication
- Exposed SSH services
- Unauthorized keys
- Excessive privileges

---

# 19. Package Management

**Definition:**  
Package management is the process of installing, updating, removing, and managing software packages and their dependencies.

### Debian/Ubuntu

Common tools:

```bash
apt update
apt upgrade
apt install <package>
apt remove <package>
apt search <package>
apt show <package>
```

### RHEL/Fedora

Common tools include:

```bash
dnf install <package>
dnf update
dnf remove <package>
```

**Interview Answer:**  
"Package managers automate software installation, updates, removal, and dependency management. Ubuntu commonly uses APT, while modern RHEL and Fedora systems commonly use DNF."

**Security Relevance:**  
Regular updates help address known vulnerabilities. Security teams should also consider trusted repositories, package integrity, dependency risks, and software inventory.

---

# 20. Logs

**Definition:**  
Logs are records of system, application, authentication, security, and other events generated by software and operating-system components.

**Common locations:**

```text
/var/log/
```

Examples on many Linux systems include:

```text
/var/log/auth.log
/var/log/syslog
/var/log/kern.log
```

On systems using systemd, logs can also be queried with:

```bash
journalctl
journalctl -u ssh
journalctl -b
journalctl --since "1 hour ago"
```

**Interview Answer:**  
"Linux logs record important events such as authentication attempts, service activity, kernel events, and application errors. I would use logs during troubleshooting and security investigations to establish what happened and when."

**Security Relevance:**
- Failed/successful logins
- SSH activity
- Service failures
- Privilege changes
- Suspicious process activity
- System errors
- Incident timelines

# Linux Security Interview Questions

## Q1. Why is Linux important in cybersecurity?

**Answer:**  
"Linux is widely used for servers, cloud infrastructure, security tools, containers, and security appliances. Understanding Linux helps me perform system administration, log analysis, process analysis, privilege management, troubleshooting, and security testing."

---

## Q2. What is the difference between `/etc`, `/var`, and `/home`?

**Answer:**  
"`/etc` contains system configuration, `/var` contains changing operational data such as logs and application state, and `/home` contains users' personal directories."

---

## Q3. What is the difference between a process and a service?

**Answer:**  
"A process is a running instance of a program. A service is a background function or application managed to provide a specific capability, and it is often represented by one or more processes."

---

## Q4. What is systemd?

**Answer:**  
"systemd is a system and service manager used by many modern Linux distributions. It handles system initialization and can manage services, timers, sockets, mounts, and other units."

---

## Q5. What is the difference between `chmod` and `chown`?

**Answer:**  
"`chmod` changes permissions, while `chown` changes ownership."

---

## Q6. Explain `chmod 755`.

**Answer:**  
"`755` gives the owner read, write, and execute permissions, while the group and others get read and execute permissions."

```text
Owner  = rwx = 7
Group  = r-x = 5
Others = r-x = 5
```

---

## Q7. What is the difference between `sudo` and root?

**Answer:**  
"Root is the privileged administrative identity. `sudo` is a mechanism that allows authorized users to execute specific commands with elevated privileges according to policy."

---

## Q8. How would you check running processes?

**Answer:**  
"I can use commands such as `ps aux`, `ps -ef`, `top`, `htop`, `pgrep`, and `pstree`. For a security investigation, I would look at the process owner, command line, parent process, resource usage, and whether the process is expected."

---

## Q9. How would you check whether SSH is running?

**Answer:**

```bash
systemctl status ssh
```

Depending on the distribution/service name, it may also be:

```bash
systemctl status sshd
```

I can also check listening sockets:

```bash
ss -lntp
```

---

## Q10. How would you investigate a suspicious Linux login?

**Answer:**  
"I would first identify the account and time of the login, then review authentication logs or the system journal, source IP information where available, SSH configuration, active sessions, recent commands where appropriate, account changes, SSH authorized keys, scheduled tasks, and suspicious processes. I would correlate these events with other security telemetry before concluding that the login was malicious."

---

## Q11. Where would you look for Linux logs?

**Answer:**  
"I would first inspect `/var/log` and use `journalctl` on systemd-based systems. The exact log files vary by distribution and service."

---

## Q12. What is `/proc` used for?

**Answer:**  
"`/proc` is a virtual filesystem provided by the kernel. It exposes runtime information about processes and system resources and is useful for troubleshooting and security investigations."

---

## Q13. What is cron and why is it relevant to security?

**Answer:**  
"Cron schedules commands to run automatically. It is useful for legitimate automation, but attackers can also abuse scheduled tasks for persistence, so security investigations should review unexpected cron jobs."

---

## Q14. What is the difference between `apt update` and `apt upgrade`?

**Answer:**  
"`apt update` refreshes the local package metadata from configured repositories. `apt upgrade` uses the available package information to upgrade installed packages where possible."

---

## Q15. Why should Linux systems be patched?

**Answer:**  
"Updates can fix known vulnerabilities, bugs, and other security issues. A secure patching process should use trusted repositories, test important updates where appropriate, and maintain an inventory of installed software."

# Linux Interview Answer Formula

For most Linux questions, use:

**Definition → How it works → Security relevance → Example**

### Example: `sudo`

**Definition:**  
"`sudo` allows an authorized user to execute a command with elevated privileges."

**How it works:**  
"It checks the configured sudo policy and, if authorized, executes the command with the permitted identity and privileges."

**Security relevance:**  
"Overly broad sudo permissions can allow privilege escalation."

**Example:**

```bash
sudo systemctl restart nginx
```
