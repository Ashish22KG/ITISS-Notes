# Project Interview Answer — Secure Multi-Office Enterprise Network

## 1. Explain Your Project to Me

### Interview-Ready Answer

> My project was **Secure Multi-Office Enterprise Network Infrastructure**, where I simulated a real-world enterprise network with two branch offices, **Pune and Mumbai**.
>
> I built the environment using **VMware Workstation Pro**, with **pfSense** acting as the firewall and gateway, **Windows Server with Active Directory** for centralized user and system management, **Ubuntu Server** for Linux-based services, and **Windows clients** for end-user systems.
>
> I configured **network segmentation, firewall rules, static routing, and secure site-to-site VPN connectivity** between the Pune and Mumbai offices so that resources could communicate securely between the two branches.
>
> For security, I implemented **Suricata as an IDS/IPS** to detect suspicious network traffic and **Fail2Ban** to protect services against repeated authentication attempts. I also used **Uptime Kuma and Nagios** for monitoring the availability and health of network devices and services.
>
> As a cloud and DevOps component, I provisioned an **AWS EC2 instance**, deployed a **Dockerized website**, and demonstrated how an application can be containerized and deployed on cloud infrastructure.
>
> The main objective of the project was to demonstrate how **networking, enterprise security, system administration, monitoring, virtualization, cloud, and DevOps technologies** can work together to build a secure multi-office enterprise environment.

# 9. Troubleshooting Question You Should Prepare

### Interviewer:
**"Suppose Pune cannot communicate with Mumbai. How would you troubleshoot it?"**

### Answer:

> First, I would check basic connectivity and confirm that both interfaces are up. Then I would verify the IP addresses, subnet masks, and default gateways. After that, I would check the routing tables and confirm that the correct static routes exist for the remote network. I would then verify that the VPN tunnel is established and check the firewall rules on both pfSense devices. Finally, I would use tools such as `ping` and `traceroute` or `tracert` to identify where the communication is failing.
